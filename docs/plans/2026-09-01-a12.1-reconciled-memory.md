# A12.1 — Reconciled model memory and revision-bound task context — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`
> (or `superpowers:executing-plans` for inline execution). Tasks are dispatched one at
> a time; the reviewing session reads every diff before the next task starts. Steps use
> checkbox (`- [ ]`) syntax. T4 and T5 may run in parallel; everything else is ordered.
>
> **Deviation from the writing-plans skill, stated deliberately, exactly as the A12.0
> plan stated it:** the operator has assigned roles — the planner (Fable) writes this
> plan and reviews; the executors (Opus) write all production code. Therefore this plan
> pins *interfaces, SQL, formats, refusal sentences, policy grammar and test
> obligations* exactly, and leaves C function bodies to the executor. Where the skill
> says "show the code", this plan shows the contract the code must satisfy. Everything
> else in the skill applies: bite-sized steps, TDD, frequent commits, no placeholders,
> no "similar to Task N".

**Goal:** Atlas reads the memory files a model is actually given — repository, project
and user — turns each discrete assertion in them into an A9.2 claim carrying its own
provenance, evaluates each one against the thing that decides it (deterministic
verification against source for an implementation fact, the effective approved decision
revision for intent), and hands a planner or executor a bounded Context Pack pinned to
a repository commit, a decision set and a memory generation, which is never reported as
current after any pinned input moves.

**Architecture:** One new layer, `src/memory`, sitting *between* the existing pieces
and inventing none of them. Memory sources are registered by the root-owned policy and
read by the principal that can read them (A13's answer, one layer out). Extraction is
deterministic and writes through `atlas_verify_intake_apply_in_tx` — the A9.2 write
point — over one deliberately added internal channel, so a memory assertion becomes a
claim plus an attestation by a DOCUMENT actor and never a second truth store. The pass
runs as a writer-thread job in A1's observe-then-apply shape. The pack is frozen per
run exactly as A10.1's memory manifest is (`UNIQUE(run_uid)`, in the run-creating
transaction), and is injected beside the one place A10.1 already injects.

**Sentence the season exists for:**
> **MODEL MEMORY IS AN ATTESTATION, NOT PROJECT TRUTH.**

**Tech stack:** C17, SQLite (numbered transactional migration 29), the first-party
line parser used by every Atlas policy file (no yyjson — its contract stays "untrusted
JSON on the IPC boundary only"), the existing A9.2 verification machinery, the existing
A13 mirror-or-tree read path, the existing A9.2.3 sweep discipline.

**Spec:** `docs/roadmap.md`, section "Next, P0: A12.1 — reconciled model memory and
revision-bound task context", including its nine numbered acceptance items and its five
named non-goals. The §Design section below carries the full argument; §Acceptance maps
every one of the nine items to the task that discharges it.

## Global constraints (repo-wide, every task inherits these)

- Warnings are errors (`ATLAS_WERROR=ON`). No new third-party dependency, no
  `FetchContent`, no network at build time. No shell: `atlas_proc_run` with an explicit
  argv array and an absolute `argv[0]` is the only way a process is created. No Python,
  Node, Go or Rust anywhere in the build, tests or runtime.
- **Never modify a registered target repository.** A12.1 adds no writer. It composes a
  commit trailer block and a proposed patch and hands both to a person; nothing in
  `src/memory` writes a repository, and the adversarial suite proves it with
  `fx_tree_digest`.
- A1's concurrency rules bind every task here: one writer thread owns the only writable
  handle; **no git process and no file read happens inside a write transaction** —
  passes observe, select, hash, then apply; never `BEGIN IMMEDIATE` across unbounded
  work. The reconciliation pass is split into an observe phase and an apply phase for
  exactly this reason (§Decision 9).
- Tests always override the data directory (`fx_open` / `--data-dir`); daemon tests
  additionally override `XDG_RUNTIME_DIR`; no test opens the real database or the real
  socket, and no test installs, enables or starts a systemd unit.
- A new `.c` file goes in the explicit `atlas_core` source list in `CMakeLists.txt` —
  there is no `file(GLOB)`, and a file that is not listed is not compiled. A new test
  goes in `ATLAS_TESTS` in `tests/CMakeLists.txt` **and** in one of the
  `set_tests_properties(... LABELS ...)` lines.
- A new command touches **five** places: a service function, a method on
  `atlas_renderer_vtbl` in `src/cli/render.h`, implementations in **both**
  `render_human.c` and `render_json.c` at the same positional offset, dispatch plus
  help text in `src/cli/cli.c`, **and** the `COMMANDS[]` table in `is_a_command`. Then
  run the built binary once.
- Every fallible function returns `atlas_status` and takes an `atlas_err *`; one exit
  path per function; `atlas_buf` owns its allocation; row callbacks receive borrowed
  pointers valid only for the call.
- Untrusted text — every byte of every memory file, every proposition extracted from
  one, every trailer value read back — is `UNTRUSTED_DATA`. It is safe-encoded with
  `atlas_safe()` at the point of output, labelled, and **never** interpreted as an
  instruction to Atlas. Safe text is terminal-safe and structure-safe and is *not*
  model-safe; §Authority states what follows from that.
- Single write point per domain; every state change is a compare-and-swap; UNKNOWN is
  zero, is stored nowhere, and never parses.
- Commit after every green task in the repo's style (`feat(a12.1): ...`,
  `fix(a12.1): ...`, `test(a12.1): ...`, `docs(a12.1): ...`). No commits of unrelated
  changes; never push until the final task.

## The ten decisions this plan settles, each with its argument

### Decision 1 — A memory assertion is an attestation by a DOCUMENT actor with SELF_DECLARED identity, over evidence Atlas recorded

This is the season's sentence turned into rows. The **evidence** row says where the
bytes are — class `ATLAS_EVIDENCE_DOCUMENT`, the path or the stored snapshot, the
content hash Atlas computed, the commit for a Git-tracked source, `observed_at` — and
is produced on `ATLAS_VERIFY_CHANNEL_ATLAS`, because Atlas *performed* the reading.
The **attestation** row says who asserts the proposition: an actor of class
`ATLAS_ACTOR_DOCUMENT`, one per registered source, identity
`ATLAS_ACTOR_IDENTITY_SELF_DECLARED`.

The identity is the load-bearing choice and the arithmetic decides it. With
`ATLAS_ATTESTED` the prior is `min(400, 900) = 400`; with `SELF_DECLARED` it is
`min(400, 350) = 350`. Four hundred would put a memory file above a self-declared AI
agent (350) and second only to a human (500) — a sentence anybody can type into
`CLAUDE.md` would outweigh the model that wrote it speaking directly, and "more
memory" would mechanically become "more confidence". That is the exact failure the
season exists to prevent, and it would arrive as a number nobody chose.

The principled statement is the same as the arithmetic: **Atlas attested the reading,
not the assertion.** The identity axis asks how well Atlas knows the speaker is who it
says. Inside a memory file the speaker is unestablished by construction — Atlas cannot
tell a note a person typed from one a model wrote from one pasted out of another
project — and `SELF_DECLARED` is the honest name for that.

### Decision 2 — Two memory sources carrying the same proposition are one evidence group, declared

Without a declared edge the union-find (`verify.c:953`) sees two DOCUMENT-class
attestations, both eligible roots, and reports **two independent groups** —
copy-and-paste manufacturing corroboration. So the reconciler emits
`ATLAS_VERIFY_OP_DEPENDENCY_ADD` between the evidence rows of any two sources whose
*normalised* proposition text is byte-identical. The edge's declared meaning already
covers this case: the two rest on evidence that shares a root. Atlas does not claim to
know which copy came first and does not need to: every error the edge can make is in
the conservative direction — fewer independent groups, a lower score, never a higher
one. Acceptance item 1 is this decision plus Decision 1: three copies keep three rows,
three provenances and three readable attestations, and contribute one group.

### Decision 3 — The write path is one added internal channel, not a second write point and not a self-described actor

This closes the gap between Decision 1 and the intake that exists. Three facts force
the shape: `derive_actor` takes class and identity **from the channel alone**; no
channel maps to DOCUMENT; and the header rule of `verify_ops.h` — the reason
`atlas_verify_actor_class` appears nowhere in `atlas_verify_op` — is that a submitter
must never describe itself into a stronger speaker.

So the channel vocabulary gains one member, **`ATLAS_VERIFY_CHANNEL_DOCUMENT`**, and
nothing else changes shape:

- It is set only by Atlas' own code, constructing an op a transport can never
  construct — the synthetic-op precedent at `intake.c:873`, reused rather than
  invented. `atlas_verify_channel_parse` already accepts only `MODEL` and `OPERATOR`;
  it now refuses `DOCUMENT` by name for the same written reason it refuses `ATLAS`: a
  request that could name its own channel could name the one that makes its evidence
  authentic — or the one that mints a new speaker per file. Minting speakers is the
  §12 inflation: a model that could reach this channel could turn N pasted files into
  N independent groups.
- The one mapping stays the one mapping: `atlas_verify_channel_actor_class(DOCUMENT)`
  returns `ATLAS_ACTOR_DOCUMENT`, `..._actor_identity(DOCUMENT)` returns
  `SELF_DECLARED`, each as a new case in the existing switches, which have no
  `default:` — so the compiler names every other site that must decide about the new
  member.
- Which channels a request may name becomes **structural, not a comment**:
  `atlas_verify_channel_is_transport_selectable(atlas_verify_channel c)` — a switch
  with no `default:`, true for exactly MODEL and OPERATOR — is the one definition,
  and `atlas_verify_channel_parse` matches names only among channels that answer
  true. Today the parse is bare `strcmp`s, so adding a future channel forces no
  decision anywhere about whether a transport may name it; after this, the compiler
  forces one, which is the writer-switch discipline applied to channels. The
  weakening comparison at `src/ipc/server_verify.c:89` is a strict `<` behind that
  parse and is unchanged; `atlas_verify_channel_authority(DOCUMENT)` returns 1, and
  its one remaining job is the weakening order among transport-selectable channels —
  a rank comparison must never become a second way to reach a non-selectable
  channel, and with the predicate in the parse it structurally cannot.
- The channel derives an authority-*lowering* actor — base 900→400, cap 900→350 —
  which is `atlas_verify_channel_authority`'s own precedent: claiming less than you
  hold is never a forgery; it is the accurate statement.

One field is added to `atlas_verify_op`, and it is a reference, not a description:
`atlas_buf memory_version_uid` (EVIDENCE_ADD section). An external memory source's
absolute path can never pass `atlas_db_verify_file_hash`'s index lookup, and the §8
rule — Atlas computes the content identity itself rather than trusting a supplied
one — must survive. So the op names a stored `memory_source_versions` row by uid;
intake resolves it and copies the hash **Atlas' own row** holds. It is refused on the
MODEL and OPERATOR channels with the sentence pinned in T4 — a memory snapshot is
bound by the pass that read it — so no transport gains a byte of new surface. The
actor-description rule is untouched: the field names a row, and every fact derived
from it is Atlas' own.

There is **no second write path**: every row this season creates in a `verify_*` table
still goes through `atlas_verify_intake_apply_in_tx`, and T17 greps `src/memory/` for
`INSERT` to prove it.

### Decision 4 — Implementation drift gets its one producer, and it reads stored rows, never prose

`atlas_verify_aggregate.conflict` has never been assigned. The producer this season
adds is one pure function in `src/verify/verify.c`:

```c
/* The one producer of a non-NONE conflict. Pure: aggregate plus two facts the
 * assessment established from stored rows. First match wins. */
atlas_verify_conflict atlas_verify_conflict_settle(const atlas_verify_aggregate *a,
                                                   bool decision_bound,
                                                   bool decision_effective);
```

Rules, in order: (1) `deterministic_fail && decision_bound && decision_effective` →
`ATLAS_CONFLICT_IMPLEMENTATION` — Atlas mechanically established that the
implementation-side fact is false while the named decision's effective approved
revision stands, which is precisely "approved knowledge says one thing and the
implementation does another", and it is a finding against the implementation;
(2) `deterministic_fail && support_count > 0` → `ATLAS_CONFLICT_CONTRADICTION`;
(3) `support_count > 0 && contradict_count > 0` → `ATLAS_CONFLICT_CONTRADICTION`;
(4) `ATLAS_CONFLICT_NONE`.

`decision_bound` and `decision_effective` are derived inside `atlas_verify_assess`
from the claim's own stored `document_uid` — extraction sets it to the DECISION
anchor's document uid at CLAIM_CREATE — and from
`atlas_db_decision_approved_revision` (`src/db/db_decision.c:1270`). No memory table
is read in `src/verify`, no prose is compared anywhere, and the decision is not
touched: the conflict is a computed property of the assessment, recomputed wherever
assessments are computed. Because rule (3) newly produces CONTRADICTION for existing
data shapes, **`ATLAS_VERIFY_ALGORITHM` is bumped** — the extending.md rule that a
changed aggregation is a new algorithm string, so no stored result is silently
reinterpreted. The four conflicts still without a producer (SUPERSESSION,
SCOPE_MISMATCH, STALE_EVIDENCE, COMPETING_NORMATIVE) are recorded in the backlog as
exactly that, not wired to anything.

What makes a claim mechanically checkable at all is assigned at extraction, from
anchors and from nothing else: a claim whose proposition carries a SYMBOL anchor gets
`SYMBOL_PRESENT`; PATH-only gets `CONTENT_HASH`; a proposition with **only** a
DECISION anchor is NORMATIVE and gets no verifier, because a deterministic verifier
may only establish a DESCRIPTIVE claim — A9.2's rule, not weakened. A proposition
carrying a DECISION anchor **and** a PATH or SYMBOL anchor is DESCRIPTIVE with
`document_uid` set: it asserts an implementation fact while citing intent, which is
the one configuration whose failure is drift. Atlas does not detect drift by
understanding sentences; it detects it where its own deterministic check and its own
decision store already disagree.

### Decision 5 — Extraction is deterministic, and a proposition that anchors to nothing does not become a claim

**Deterministic, for three reasons, of which the third is the one that matters.** A
model call is a process, and A1 forbids creating one inside a write transaction. A
model call is unbounded, and A9.2.6/A9.2.7 forbid an unbounded job holding the writer
without a yield. And — the real reason — if a model decided which sentences in a
memory file are propositions, the reconciliation would itself be an unrecorded model
inference standing between the file and the claim table. The season's sentence would
be violated at the first step, by the machinery built to enforce it.

**Anchored.** `verify.h`'s claim contract states the rule this follows: small claims
verify and large ones do not; "the protocol is secure" is not a claim, it is a topic.
So the extractor splits a source into bounded candidates — a list item, or a
paragraph — normalises each, and looks for at least one **anchor**: a backtick-quoted
repository-relative path that resolves in `files`, a backtick-quoted symbol that
resolves in the structural index, an `atlas-dec-<hex>` decision uid that resolves in
the decision store, or a bare 40-hex oid that resolves in `commits`. Resolution is
against the index, never by asking git — the pass applies on the writer thread. A
candidate with at least one anchor becomes a claim through intake. A candidate with
none is stored as an **unanchored proposition** — source, ordinal, hash, text — and is
*reported*, never discarded and never made into a claim. That is A9.2.2 applied to
extraction: did-not-extract is not proven-to-contain-nothing, and a candidate nobody
is shown is indistinguishable from one that does not exist. The pack reports the
unanchored count as a gap.

The extractor carries its own epoch, `ATLAS_MEMORY_EXTRACTOR_VERSION` — A3's
`ATLAS_CODE_ANALYZER_VERSION` rule: identical bytes must not silently produce
different propositions, so a change to the split, the normalisation or the anchor
syntax bumps the epoch, and the epoch is part of the reconciler actor's stored
version.

### Decision 6 — Which principal reads a source is decided by where its bytes are, and the daemon opens no path it was not given

Four registered classes, and the reading principal for each:

| Class | Where | Read by | Version chain |
| --- | --- | --- | --- |
| `REPO_FILE` | one exact repository-relative path | the daemon, through `atlas_repo_open_git` — mirror or tree per A13; `git cat-file` for a tracked path | Git: commit + blob |
| `REPO_DIR` | direct children of one repository-relative directory named `*.md` | as above; no descent, bounded count | Git where tracked, Atlas snapshot where not |
| `EXTERNAL_FILE` | one exact absolute path outside every registered repository | **the operator's own CLI** (`atlas memory scan`), submitting through `memory.put` | Atlas snapshot chain |
| `EXTERNAL_DIR` | direct `*.md` children of one absolute directory | as above | Atlas snapshot chain |

`EXTERNAL_*` is where the design could most easily have gone wrong. The tempting shape
is to let the daemon open the absolute path the policy names. Refuse it: it gives the
daemon a filesystem read path outside its data directory for the first time in Atlas'
history — and it does not even work, because `~/.claude/CLAUDE.md` is unreadable to
`atlasd` on exactly the separated deployment A7.1 exists to produce. The A13 answer is
already proved on this machine: the principal that can read the bytes hands them to
the daemon, and the daemon indexes what it cannot open. `memory.put` is that, for a
file instead of a tree. The root-owned policy still decides **which** sources exist:
`memory.put` names a registered source and is refused for anything else.

A version row that binds a blob (`blob_oid` non-empty) stores no content — Git is
canonical for those bytes, invariant 2 — and one that binds no blob stores the bytes
themselves, because nothing else holds them. **Those snapshot rows are not
rebuildable, and invariant 1 does not cover them** — O10's argument for verification
records, restated here so nobody "cleans them up".

**Stated costs, documented rather than solved:** an `EXTERNAL_*` source is only as
fresh as the last `atlas memory scan`; the pack reports when it was last observed and
never claims it is current. And a policy line with no `@repo` qualifier materialises
per registered repository, so a machine-wide user-memory file produces claims in every
repository it is registered against — bounded by the source and claim ceilings, and
stated in `memory status` rather than hidden.

### Decision 7 — `memory_generation` is stored, monotonic per repository, and produced by exactly three causes

A generation is history — the argument A8-CI makes for `sem_generations` — so it is
stored, not derived. Exactly three causes: an accepted **source revision** (a
registered source's content hash moved), an effective **decision revision** (what the
effective approved revision *is* changed), and a repository **commit** whose bounded
impact set touches an anchored claim. One pass that observed changes appends one
generation; when several causes held, the stored cause is the first of
SOURCE_REVISION, DECISION_REVISION, COMMIT that held, and the per-claim diff rows
carry the rest. A pass that changed nothing appends no generation.

Every generation carries a **semantic diff**: per claim, one of `ADDED`, `CHANGED`,
`SUPPORTED`, `CONTRADICTED`, `STALE`, `IMPACTED`, `SUPERSEDED`, `UNKNOWN` — the
roadmap's list, frozen as `atlas_memory_diff_kind` with UNKNOWN at zero. A claim no
event touched gets **no row**, which is what makes acceptance item 2's "unrelated
claims byte-for-byte stable" checkable rather than asserted. **A working-tree change
makes the view dirty and does not produce a generation**: dirty is a live fact the
pack reads and refuses to be current under; a generation is produced by an *accepted*
revision. A generation per keystroke is the roadmap's own named non-goal.

### Decision 8 — The pack is frozen per run in migration 29's own table, staleness is compared, and reliance is read from anchors by the principal that can see the tree

The pack pins six values: `repo_identity_hash`, the indexed commit
(`repositories.scanned_head` — the state Atlas can honestly bind, `bind_commit`'s own
rule), the live source identity when the row says the tree is dirty (reusing
`atlas_sem_source_identity`, the one implementation of that question), the
`memory_generation`, the decision-set digest, and the source-set digest. It is built
from stored rows only — no process, no file read — so it can be **frozen inside the
transaction that creates the run**, beside `atlas_db_orch_memory_freeze`
(`db_orch.c:912`), in its own table `memory_context_packs` under `UNIQUE(run_uid)`.
A10.1's `orch_run_memory` is **not** reused: that table's columns describe a
cross-run retrieval manifest, and a row that meant two different objects depending on
the season that wrote it would be unreadable in both.

The stored row is what the season's three consumers read: the freeze (the row is the
freeze), the trailer verification (`pack_digest` over the rendered body), and the
post-run reliance check (`claims_manifest` and `flagged_anchors`, netstring-encoded —
M23's manifest precedent). The `status:` line is **not** stored: freshness is
recomputed on every read (A6: nothing cached, no dirty bit) and the line is composed
at delivery, so the stored body stays deterministic — the same pinned inputs
reproduce the same bytes and the same digest.

`CONTEXT_CONFLICT` is reported for a claim in the pack's relevant set whose stored
assessment carries `ATLAS_CONFLICT_CONTRADICTION` or `ATLAS_CONFLICT_IMPLEMENTATION`.
Relevance is A10.1's discipline verbatim: deterministic lexical overlap between the
task text and the claim's text plus anchor values, a total order ending in the claim
id, bounded at `ATLAS_MEMORY_PACK_MAX_CLAIMS`; **never recency**. Unrelated stale
material is reported and excluded rather than gating — a gate that fires on
everything trains everybody to ignore it.

**The reliance check reads anchors, never prose.** A12.0 froze the rule: model prose
never routes control flow, and there is no `strstr` over a plan, a log or an artifact
on any such path. And A13 fixes the division of labour: the daemon cannot read a
scanner-named tree, the mirror reflects the scanner's last pass rather than the
worker's uncommitted edits, and the run driver holds the tree as the operator
principal. So **the driver gathers, the daemon intersects**: after the worker and the
existing HEAD re-check, the driver lists the changed paths (`git status --porcelain
-z`, already allowlisted), sends them on the completion op, and the daemon intersects
them with the frozen pack's flagged PATH anchors inside the completion transaction.
`touched_paths` is the driver's own observation — the same trust class as
`op->success`, which is Atlas' classification and not the worker's claim; a hostile
completion could suppress a report and can never manufacture authority, because the
result is `RELIANCE_SUSPECTED`, it is recorded on the pack row, and **it settles
nothing**: no gate fails, no run blocks, no verdict moves. Touching a file a stale
claim mentions is evidence the claim was in scope, not proof the worker believed it,
and a check that pretended otherwise would be a confident wrong answer on Atlas' most
authoritative surface.

### Decision 9 — The pass is observe-then-apply on the writer thread, and what triggers it is a pure derivation plus an operator's word — never a timer

The draft signature that did read → extract → intake "inside the caller's
transaction" violated A1: reading a source is a file open and a `git cat-file`
process, and **no git process and no file read happens inside a write transaction**.
The pass is therefore two pinned phases, both running inside one writer job, exactly
as the watcher's reconciliation already does on that thread: `atlas_memory_observe`
runs first with no transaction open — it reads every registered source through
Decision 6's principals, hashes, splits and normalises — and
`atlas_memory_apply_in_tx` runs second inside the transaction the job opens,
performing only database work: anchor resolution against the index, the intake ops,
version rows, generation and diff.

Two triggers, and no third:

1. **The operator asks.** `memory.reconcile` (operator RPC) enqueues the job; the
   daemonless CLI form takes the write lock and runs the same two phases locally.
   Manual and automatic are one pipeline — A9.2.3's rule.
2. **The watcher's tick derives that a pass is owed.** `atlas_memory_plan_for` is a
   pure read — no dirty bit, no state of its own — comparing stored facts only: each
   registered `REPO_*` source's current hash **in the `files` index** against its
   latest version row, the latest `EXTERNAL_*` version against the last generation's
   source-set digest, the effective decision set against the stored digest, and
   `scanned_head` against the last generation's head. All four are index reads,
   because every repository source's current hash is already in `files` (the index
   carries tracked and untracked alike — A13), so the derivation costs no file read
   and no process. `memory_sweep`, called from the watcher tick beside `sem_sweep`,
   asks it on `ATLAS_MEMORY_SWEEP_INTERVAL_MS` and enqueues when it answers yes —
   gated on the root policy's `memory_reconcile = ENABLED`, whose default is the
   compiled-in **false**: reconciliation reads files and writes claims, and A9.2.4's
   reversal of an off-default was argued from a resource-and-authority case this
   season has not made. The scheduler and `memory status` ask the same function,
   which is what keeps them one answer.

The cadence chain, written out: an edit to a repository memory file reaches the
`files` index through the watcher's own event or reconcile pass; the sweep sees the
index move at its next tick; the pass runs and appends a generation. Convergence, not
immediacy — and the lag is stated in `memory status` rather than hidden.

### Decision 10 — Two writer job kinds, each answering both switch questions with its reason at the case

Gap-closing follow-through of Decision 9: the two switches in `src/daemon/writer.c`
have no `default:`, so the build fails until both questions are answered for both new
kinds, and `tests/test_daemon_responsive.c` compares the answers against documented
sets.

- **`ATLAS_JOB_MEMORY`** — `memory.put` and the small typed writes. Unbounded:
  **false** (a handful of statements over handed-in bytes ≤
  `ATLAS_MEMORY_MAX_SOURCE_BYTES`). Drainable: **true** — an operator's CLI is
  waiting, and the tables written (`memory_sources`, `memory_source_versions`) are
  disjoint from everything a semantic pass or discovery walk touches, the same two
  conditions `ATLAS_JOB_VERIFY` satisfies.
- **`ATLAS_JOB_MEMORY_RECONCILE`** — the pass. Unbounded: **false**, and the
  checklist's own test decides it: the duration is statable from compiled bounds —
  at most 16 sources of at most 256 KiB, at most 2048 candidates, at most 256
  claims — work bounded by statement and source counts, not by the repository.
  Answering true for a job this frequent would be the data-loss choice the checklist
  warns about, and RECONCILE beside it already answers false for a far longer pass.
  Drainable: **false**, reason at the case: the pass reads sources and forks git in
  its observe phase, and a yield must stay a pause, not a tunnel through which file
  I/O reaches the thread.

## Frozen formats

### Policy grammar (root-owned system policy, the A7.1 file)

Repeated key, `client_uid`'s precedent exactly:

```
memory_source = REPO_FILE:CLAUDE.md
memory_source = REPO_DIR:.claude/memories
memory_source = EXTERNAL_FILE:/home/example/.claude/CLAUDE.md
memory_source = EXTERNAL_DIR@atlas:/home/example/.claude/projects/-opt-atlas/memory
memory_reconcile = ENABLED
```

- The value is `<CLASS>[@<repo>]:<path>`, split at the **first** colon; the head is
  then split at the first `@`. Class is one of the four spellings and nothing else;
  an unrecognised class is MALFORMED.
- `@<repo>` scopes the source to one registered repository by name: 1..64 bytes, no
  NUL, no `/`, not `.` or `..`, else MALFORMED. Absent `@`, the source materialises
  for **every** registered repository. A name no registry row currently matches is
  valid grammar and simply materialises nothing — repositories come and go while the
  policy stands, and a policy killed by an unregistration would be a new failure mode.
- A `REPO_*` path is repository-relative: not absolute, no `..` **component** (a
  literal `a..b.md` is legal), not beginning `.git/`. Any violation is MALFORMED.
- An `EXTERNAL_*` path must be absolute, else MALFORMED.
- The `.md` suffix for `*_DIR` forms is compiled in (`ATLAS_MEMORY_DIR_SUFFIX`), not
  configurable: a suffix list is a glob with extra steps.
- At most `ATLAS_MEMORY_MAX_SOURCES` (16) `memory_source` lines; the seventeenth is
  **MALFORMED, not truncated** — `client_uid`'s rule, for its reason: a silently
  shortened list is one whose author and reader disagree about what is on it.
- `memory_reconcile` is `ENABLED` or `DISABLED`, at most once; anything else is
  MALFORMED. Absent resolves to the compiled-in `ATLAS_MEMORY_RECONCILE_DEFAULT`,
  **false**.
- An unrecognised key anywhere is still MALFORMED and still drops the whole policy to
  legacy — **so the binary is installed before the keys are written**, P0's rule,
  restated because it bites on every policy change.

### The commit trailer block

Composed by Atlas for a person (or a driver's final report) to paste into a commit
message; Atlas itself commits nothing, and a worker's scope-lock already forbids
committing. Every value is an Atlas-owned identifier or a hex digest; no value is
prose:

```text
Atlas-Provenance: v1
Atlas-Run: <run uid>
Atlas-Memory-Generation: <integer>
Atlas-Context-Digest: sha256:<64 hex>
Atlas-Decision-Set-Digest: sha256:<64 hex>
Atlas-Change-Reason: <ai_reasons record uid>
```

**A trailer is a pointer, never proof and never authority.** On ingestion Atlas
resolves every reference against its own rows — the run, the generation, the pack
digest, the decision-set digest, the reason record — and a reference that is missing,
unknown or does not verify leaves that field `UNKNOWN` and **binds nothing**: it can
never manufacture an approval, a gate result or a verified claim. A commit with no
trailer block is ordinary valid history and is recorded as carrying none, which is a
different fact from carrying a bad one. Prompts, memory bodies, credentials, secrets,
model names and costs never appear — enforced by construction: the composer has no
parameter that could carry one.

### The pack, as rendered to a worker

```text
--- atlas-context-pack-1 ---
status: CURRENT | STALE:<which pinned input moved>     <- composed at delivery, never stored
repo_identity: <64 hex>
commit: <40 hex>
source_identity: <64 hex | absent when the indexed tree was clean>
memory_generation: <integer>
decision_set: sha256:<64 hex>
sources: <n> registered (<m> external, oldest observation <ISO-8601>)
claims: <n> included, <k> excluded as unrelated-stale, <u> unanchored propositions
[per claim]
  claim <uid> <SUPPORTED|CONTRADICTED|UNKNOWN|CONTEXT_CONFLICT> confidence_score=<0..100>
    text: <atlas-safe-1 encoded, UNTRUSTED_DATA>
    from: <source uid>@<version uid>  anchors: <kind>:<value>...
    [evidence and counter-evidence, one line each, encoded and labelled]
--- end atlas-context-pack-1 ---
```

Every text field is `atlas_safe()`-encoded and labelled. The preamble the composer
prepends states the section is reference material, that Atlas ran no judgement over
it, and that instruction is not enforcement. **What makes the pack harmless is that no
branch reads it** — A10.1's rule verbatim; one `strstr` over it anywhere would end the
argument. `confidence_score` is the JSON key's own spelling: a score, never a
probability.

## Authority argument — the season's non-negotiables

These go into `docs/engineering-rules.md` in full and into `CLAUDE.md` as one line
each (T18).

- **MODEL MEMORY IS AN ATTESTATION, NOT PROJECT TRUTH.** A memory file is a DOCUMENT
  actor at SELF_DECLARED identity, weighted 350 of 1000, and a claim it asserts is
  UNVERIFIED until something that is not a memory file bears on it.
- **The reconciler creates no competing truth database.** Every verification row goes
  through `atlas_verify_intake_apply_in_tx`; there is no second write path, and adding
  one is not an extension of this season — O10's rule, unchanged.
- **`ATLAS_VERIFY_CHANNEL_DOCUMENT` is internal, and the parse refusal is the guard.**
  No transport can name it, no rank comparison may ever admit it, and it only lowers:
  DOCUMENT/SELF_DECLARED against ATLAS/ATLAS_ATTESTED is 400 against 900 and 350
  against 900.
- **The reconciler cannot approve, reject, supersede or resolve anything.**
  `atlas_decision_apply_in_tx` keeps exactly three callers and `src/memory` is not
  one. Drift is `ATLAS_CONFLICT_IMPLEMENTATION` — a finding against the
  implementation — and never a rewrite of the decision; a later timestamp supersedes
  nothing; the conflict producer reads stored rows and never prose.
- **The daemon opens no path the policy names.** Repository sources go through
  `atlas_repo_open_git`; external sources are carried to the daemon by a principal
  that can read them; `atlas memory scan` opens with `O_NOFOLLOW` and a symlinked
  registered path is refused, not followed.
- **Extraction calls no model, and no branch anywhere reads a memory byte, a pack
  byte or a worker's prose.** The reliance check intersects Atlas-resolved anchors
  with driver-observed paths and settles nothing.
- **A trailer confers nothing.** Resolution and digest verification are the whole of
  ingestion, and every failure mode is UNKNOWN.
- **Registry churn deletes no memory history.** No memory table references
  `repositories` — `verify_claims`' own shape — and nothing in this season deletes a
  `memory_sources` row; a re-registered repository starts a fresh chain and the old
  rows stand as history.
- **Atlas never writes a memory source.** A hand-authored file receives a proposed
  patch that only deletes what Atlas can show contradicted or superseded, and never
  contains a sentence Atlas authored; applying it is a person's act.
- **No new thread, process, timer or background loop; no MCP tool; no gateway route;
  no authority verb in any method name.** The pass is a bounded writer job triggered
  by a pure derivation on the existing watcher tick, or by an operator.

## Worst-case cost, stated so nobody discovers it in a bill

Per repository per pass: ≤ `ATLAS_MEMORY_MAX_SOURCES` (16) sources ×
`ATLAS_MEMORY_MAX_PROPOSITIONS` (128) = 2048 candidates, of which at most
`ATLAS_VERIFY_MAX_CLAIMS` (256) become claims — the existing intake bound, reached
and reported rather than silently exceeded. Each source read once, bounded at
`ATLAS_MEMORY_MAX_SOURCE_BYTES` (256 KiB), refused above rather than truncated; ≤ 4
intake ops per anchored proposition; trailer scan ≤ `ATLAS_MEMORY_TRAILER_SCAN_MAX`
(512) commits per pass with the cursor carrying the remainder forward. **Zero model
calls.** The only paid runs are acceptance item 8's pilot (T19), gated on the
operator's explicit go-ahead: a real-model arm on this project is measured at roughly
$5.

### Task T3: migration 29, and a retention row for every table

**Files:**
- Modify: `src/db/migrate.c`, `include/atlas/db.h`, `src/core/service_maintenance.c`
- Test: `tests/test_migrate.c` (extend) + the hand-maintained wind-back fixture

Eight tables, all additive; nothing rebuilt, so foreign keys stay enforced and no
pre-existing row is rewritten; nothing backfilled — no repository that predates this
migration has a registered source, and inventing one is migration 19's mistake.

**No memory table references `repositories`, and that is a decision with the tree's
own precedent, not an omission.** The two domains this layer annotates both made the
call already: `verify_claims.repo_id` is a plain `INTEGER NOT NULL DEFAULT 0` with no
foreign key (`src/db/migrate.c:2760`), and no `orch_*` table carries a `REFERENCES
repositories` clause at all — verified by grep during planning. A4 states the rule
those shapes follow: registry churn must not delete history, because a `repositories`
row is a mutable operational fact and the record outlives it. The memory rows are
that kind of record — snapshot versions nothing can rebuild, the generation ledger,
the semantic diff, the pack a worker was shown, the bindings trailers verified
against — and a cascade here would have deleted the diff history while the
`verify_claims` rows it describes survived: a half-deleted history, worse than
either whole choice. So `repo_id` is a plain column on every memory table, exactly
`verify_claims`' shape. Intra-domain foreign keys (versions→sources,
diffs→generations, unanchored→versions) keep their cascades for referential hygiene;
nothing in this season deletes a `memory_sources` row, and the season rule says so.
**Stated cost:** a repository removed and registered again gets a new `repositories`
id and starts a fresh generation chain; the old rows remain readable history keyed
by the old id and by `repo_identity_hash` on the generation rows, and re-attaching
them is A4-grade detach/attach machinery this season deliberately does not build —
a backlog entry, not a silent behaviour.

```sql
CREATE TABLE memory_sources (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  -- Plain on purpose, verify_claims' shape: registry churn deletes no memory
  -- history. The argument is in the migration comment above.
  repo_id INTEGER NOT NULL,
  source_uid TEXT NOT NULL UNIQUE,          -- 'm' + 32 lowercase hex
  cls TEXT NOT NULL CHECK(cls IN ('REPO_FILE','REPO_DIR','EXTERNAL_FILE','EXTERNAL_DIR')),
  path_raw BLOB NOT NULL,                   -- exact bytes; paths are not text
  path_text TEXT NOT NULL,                  -- lossless %XX encoding, for display
  registered_at TEXT NOT NULL,
  UNIQUE(repo_id, cls, path_raw)
);
CREATE INDEX idx_memory_src_repo ON memory_sources(repo_id, id);

CREATE TABLE memory_source_versions (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  source_id INTEGER NOT NULL REFERENCES memory_sources(id) ON DELETE CASCADE,
  version_uid TEXT NOT NULL UNIQUE,         -- 'v' + 32 lowercase hex
  -- Git binding where there is one; both recorded rather than one derived:
  -- 'this had no blob' and 'nobody looked' are different facts.
  commit_oid TEXT NOT NULL DEFAULT '',
  blob_oid TEXT NOT NULL DEFAULT '',
  content_sha256 TEXT NOT NULL,
  content_bytes INTEGER NOT NULL,
  -- Git is canonical for a blob-bound version; Atlas is canonical otherwise,
  -- so exactly the versions with no blob carry their bytes.
  content BLOB,
  observed_at TEXT NOT NULL,                -- when the bytes described
  recorded_at TEXT NOT NULL,                -- when Atlas wrote the row
  read_by_uid INTEGER NOT NULL,             -- which principal read them
  UNIQUE(source_id, content_sha256, observed_at),
  CHECK(blob_oid <> '' OR content IS NOT NULL)
);
CREATE INDEX idx_memory_ver_source ON memory_source_versions(source_id, id DESC);

CREATE TABLE memory_claim_anchors (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_id INTEGER NOT NULL,           -- plain by the same rule: churn deletes no history
  claim_uid TEXT NOT NULL,
  kind TEXT NOT NULL CHECK(kind IN ('PATH','SYMBOL','DECISION','COMMIT')),
  value TEXT NOT NULL,                      -- resolved reference; PATH values are path_text form
  UNIQUE(claim_uid, kind, value)
);
CREATE INDEX idx_memory_anchor_lookup ON memory_claim_anchors(repo_id, kind, value);

CREATE TABLE memory_generations (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  repo_id INTEGER NOT NULL,           -- plain by the same rule: churn deletes no history
  generation INTEGER NOT NULL,

  repo_identity_hash TEXT NOT NULL,

  source_set_digest TEXT NOT NULL,
  trailer_scan_high INTEGER NOT NULL DEFAULT 0,  -- highest commits.id examined for trailers
  created_at TEXT NOT NULL,
  UNIQUE(repo_id, generation)
);
CREATE INDEX idx_memory_gen_repo ON memory_generations(repo_id, generation DESC);

CREATE TABLE memory_claim_diffs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  generation_id INTEGER NOT NULL REFERENCES memory_generations(id) ON DELETE CASCADE,
  claim_uid TEXT NOT NULL,
  kind TEXT NOT NULL CHECK(kind IN
    ('ADDED','CHANGED','SUPPORTED','CONTRADICTED','STALE','IMPACTED','SUPERSEDED','UNKNOWN')),

  -- Never model prose.

);

-- A candidate that resolved no anchor. Stored, reported, never a claim.
CREATE TABLE memory_unanchored (
```
